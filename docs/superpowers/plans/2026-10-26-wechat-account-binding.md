# 微信身份绑定修正实施计划

日期：2026-10-26。项目：D:\code\Java\bike-assembly-mes。

## 问题与核查结果

SysUserServiceImpl.wxLogin 对新微信用户直接创建 wx_ 前缀账号、分配 operator 角色并签发正式登录凭据，导致首次登录绕过绑定。当前只有一条自动生成的微信用户记录：userId=7、昵称“微信用户”、roleId=3、创建时间2026-10-26 13:52:44。用户已要求删除该自动账号及身份关联。

## 推荐行为

1. 微信未绑定系统账号：进入“绑定已有账号”页，输入系统用户名和密码，经后端验证后绑定。绑定前只允许完成绑定，不能进入业务功能。
2. 已绑定微信：从数据库读取其系统账号当前角色和权限后登录，不自动改成工人，也不自动补默认角色。
3. 不提供用户自行选择系统角色、注册任意身份的入口。角色来自管理员已配置的系统账号。
4. 绑定账号时保留目标系统账号的用户名、昵称、角色和业务记录，只建立微信关联。处理 openid 唯一索引，避免临时微信账号和目标账号同时占用同一 openid。
5. 临时绑定凭据通过专用请求头传递，不写成正式 accessToken，避免旧登录缓存覆盖绑定鉴权。
6. 旧微信自动账号ID7清理后，本次客户端缓存中的旧登录态需退出，下一次微信登录重新绑定。

备选方案是保留首次注册并选择角色，但会继续产生独立微信账号且身份可能与已有员工账号不一致，因此推荐绑定已有账号。

## 涉及实现

- 后端 SysUserServiceImpl、WxLoginVO/WxBindDTO及必要的现有Mapper方法：恢复首次绑定的临时凭据分支，取消默认工人分配；验证绑定来源、目标账号密码和状态；按事务处理微信关联与临时记录清理。
- 前端 pages/account-bind/index.vue、api/auth.ts以及必要的登录状态处理：保留已有账号绑定表单，移除自行注册选角色，显式传临时凭据，绑定成功刷新系统身份。
- 更新相关TypeScript类型和OpenAPI描述，保持现有路径 POST /app/user/wx-login、POST /app/user/wx-bind、GET /app/user/me。
- 不修改数据库结构，不删除共享 sys_role 中的工人角色，不改其他员工账号。

## ID7数据清理

在修正后的代码部署后执行，防止旧逻辑再次生成工人账号：

1. 精确核对ID7仍为本次自动生成的wx_账号，并检查其生产工单、报工、质检、报修、安灯等业务关联。
2. 如发现业务关联，保留业务记录并停止直接删除该账号，报告具体关联。
3. 无业务关联时，保存本地回滚记录，在同一事务中清理该账号的刷新会话及必要从表，再删除ID7账号。共享角色定义保持原状。
4. 校验其他账号、共享角色和业务记录数量不受影响，旧会话不能继续访问业务接口。

## 验证与交付

- 后端回归：首次登录不签发正式会话、不自动分配工人角色；已绑定账号保留角色；绑定凭据过期、密码错误、禁用账号和重复绑定返回明确错误；成功绑定不因openid唯一索引失败；绑定完成后 /me 返回目标账号角色权限。
- 前端：类型检查、测试、生产微信构建与开发微信构建，确保 build 和 dev 同步更新。
- 重新打包并使用已有本地微信配置启动助手重启后端，密钥不进入源码和日志。
- 微信开发者工具验证首次登录进入绑定页、已有账号绑定和后续一键登录；对数据清理和登录态失效保存不含凭据的验证记录。
