## 可演示的生产场景

工单编号为 `MO-执行日期-四位序号`，下表按末四位识别。历史记录覆盖最近 28 天；每日 17 点前初始化时历史锚点取昨天，避免生成尚未发生的完工记录。

| 序号 | 当前场景 | 下一步操作 |
| --- | --- | --- |
| 0001–0036 | 历史完工或关闭，含 6 次不合格返工后复检通过 | 查看工序、初检合格率、缺陷处理和库存流水 |
| 0037–0038 | 已下达，首道工序可开工 | 执行人开工并报工 |
| 0039 | 第 3 道工序进行中，已部分报工 | 继续报工至计划数量，下一工序自动解锁 |
| 0040 | 第 6 道工序待检，未分配检验人 | 质检员领取、录入并确认 |
| 0041 | 第 7 道工序已录入合格结果，尚未确认 | 当前检验人确认结果 |
| 0042 | 第 7 道工序检验不合格 | 执行人发起返工 |
| 0043 | 第 7 道工序返工中 | 完成返工，生成下一轮复检 |
| 0044 | 工单暂停，存在物料短缺告警 | 恢复工单后继续报工 |
| 0045 | 工单生产中且逾期 | 查看重点工单、逾期指标和进度告警 |
| 0046–0047 | 未指派草稿工单，无工序记录 | 管理员指派执行人后下达 |
| 0048 | 已下达后取消 | 全部工序均为取消，不能继续生产 |

账号沿用执行数据库中启用的 planner、operator、inspector、maintainer 角色账号。没有仓库角色账号时，由管理员作为演示库存流水操作人。全新初始化仍使用 `init_database.sql` 中的开发账号；现有环境不修改密码。

## 一致性规则

待检单没有检验时间、检验人或结论；已录入单没有确认时间；已确认单有检验人、确认人及时间。复检轮次连续且关联上一次失败检验，完成的质检工序最终一轮必须合格。

库存从零余额开始，所有已执行单据都有明细与流水。余额、每笔变动前后数量由按时间排列的流水计算；移库一出一入且数量守恒。未执行单据不影响库存，库存只记在叶子库位。

有活动维修或保养的设备标记不可运行；进行中的生产工序使用正常启用设备。ERP 同步、MQ 消费及幂等技术表不预造成功记录。

`sql/verify_database.sql` 包含 41 项检查，发现不一致会抛 SQL 错误；它校验关系和状态，不把正常新增业务记录误判为数据量错误。
