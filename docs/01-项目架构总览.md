> 生成日期：2026-07-25 | 分支：dev-lzy

## 1. 项目定位

**自行车组装 MES（制造执行系统）** 是一套面向自行车组装车间的生产管理平台，覆盖从工单下达到工序报工、质量检验、仓库管理、设备维修、安灯告警、安全培训的完整制造流程。

### 1.1 解决的问题

| 问题 | 解决方案 |
|------|---------|
| 生产进度不透明，工单状态靠口头/纸质传递 | 工单 + 工序状态机，实时追踪每个工序的完成情况 |
| 质检流程不规范，结果难以追溯 | 质检单 + 检验项目 + 返工闭环，全链路可追溯 |
| 工人操作易重复提交（网络抖动/多次点击） | 客户端幂等键 + 服务端数据库幂等，防重复提交 |
| 多终端接入安全无法保障 | 管理端/移动端双通道 JWT 隔离，RBAC 权限控制 |
| 消息通知依赖轮询，实时性差 | RabbitMQ 事件驱动，异步通知各业务系统 |
| 密码安全策略缺失 | BCrypt 加密 + 密码复杂度校验 + 历史密码防重用 + 登录失败锁定 |
| 并发操作导致数据不一致 | 乐观锁版本号 + CAS 原子更新 |
| ERP 数据同步状态不可见 | ERP 同步日志记录每次同步的请求/响应/状态 |

### 1.2 适用场景

- **管理端（Web）**：计划员下达工单、管理员配置基础数据、质检员录入/确认检验结果、管理者查看报表
- **移动端（微信小程序）**：车间工人扫码/查看工单、开始/报工工序、质检员录入检验结果、仓库人员查看库存

## 4. 分层架构（苍穹外卖风格）

### 4.1 后端分层

```
┌──────────────────────────────────────────────────┐
│  Controller（@RestController）                     │
│  · 参数接收、参数校验、调用Service、返回Result      │
│  · @RequirePermission 权限控制                     │
│  · @IdempotencyRequired 幂等保护                    │
│  · @OperLog 操作日志                               │
├──────────────────────────────────────────────────┤
│  Service（接口） + ServiceImpl（@Service）          │
│  · 业务逻辑、事务管理 @Transactional                │
│  · 状态机校验 StatusTransitionValidator            │
│  · 幂等处理 IdempotencyService                     │
│  · MQ 消息发送 MessageProducerService              │
├──────────────────────────────────────────────────┤
│  Mapper（@Mapper，extends BaseMapper<T>）           │
│  · MyBatis-Plus 内置 CRUD                         │
│  · 自定义 SQL（@Select / XML Mapper）               │
│  · CAS 原子更新（防并发）                           │
├──────────────────────────────────────────────────┤
│  MySQL（bike_assembly_mes）                        │
│  · 31 张业务表 + 5 张 MQ/基础设施表                 │
└──────────────────────────────────────────────────┘
```

### 4.2 横切关注点

| 层 | 组件 | 职责 |
|----|------|------|
| 拦截器 | `JwtTokenAdminInterceptor` | 管理端 JWT 校验、用户状态、权限加载 |
| 拦截器 | `JwtTokenAppInterceptor` | 移动端 JWT 校验、临时令牌处理 |
| 拦截器 | `IdempotencyInterceptor` | 提取 Idempotency-Key 请求头 |
| AOP | `PermissionAspect` + `@RequirePermission` | 方法级权限校验 |
| AOP | `OperLogAspect` + `@OperLog` | 自动记录操作日志 |
| 全局异常 | `GlobalExceptionHandler` | 统一异常 → Result 转换 |

## 5. 请求完整调用链

```
HTTP Request
  │
  ├─ 1. IdempotencyInterceptor.preHandle()
  │     └─ 提取 Idempotency-Key 请求头 → BaseContext
  │
  ├─ 2. JwtTokenAdminInterceptor.preHandle() / JwtTokenAppInterceptor.preHandle()
  │     ├─ 校验 JWT 签名（admin/app 独立密钥）
  │     ├─ 校验 tokenType（access/refresh/temp）
  │     ├─ 校验 clientType（admin/app）
  │     ├─ 查询用户状态（禁用/密码过期/强制改密）
  │     ├─ 加载权限 → Caffeine 缓存 → BaseContext
  │     └─ 加载数据权限范围 → BaseContext
  │
  ├─ 3. PermissionAspect（@RequirePermission）
  │     └─ 比对用户权限 vs 所需权限码 → 403 ForbiddenException
  │
  ├─ 4. Controller Method
  │     └─ 参数校验（@Validated + JSR303）
  │
  ├─ 5. Service Method（@Transactional）
  │     ├─ 状态机校验 StatusTransitionValidator
  │     ├─ 幂等处理 IdempotencyService.tryAcquire()
  │     ├─ 乐观锁 CAS 更新
  │     ├─ 业务逻辑
  │     └─ MQ 消息发送（安全降级 try-catch）
  │
  ├─ 6. Mapper Method
  │     └─ MyBatis-Plus 或自定义 SQL
  │
  ├─ 7. OperLogAspect.finally → sys_oper_log
  │
  └─ 8. Interceptor.afterCompletion → BaseContext.removeAll()
```

## 8. 关键设计决策

1. **双通道 JWT**：管理端和移动端使用独立签名密钥，密码学隔离，一方泄露不影响另一方。
2. **集中式状态机**：所有合法状态转换定义在 `StatusTransitionValidator` 静态 Map 中，Service 不再散落 if/else。
3. **数据库幂等**：通过 `pro_idempotency_record` 表的唯一索引实现原子性幂等，比 Redis 方案更简单且无需额外中间件。
4. **乐观锁 + CAS**：MyBatis-Plus `@Version` 提供通用乐观锁，关键路径额外使用 CAS SQL（WHERE status=? AND version=?）消除 TOCTOU 竞态。
5. **RabbitMQ 安全降级**：MQ 发送失败不影响业务主流程，通过 `try-catch` 仅记录日志。
6. **动态路由 + 权限指令**：前端菜单由后端接口动态下发，`v-permission` 指令控制按钮级权限，后端 `@RequirePermission` 作为安全边界。
7. **Caffeine 本地缓存**：权限信息 30 分钟 TTL，角色变更通过 Spring Event 主动驱逐缓存。
8. **双 Token 机制**：短有效期 Access Token + 长有效期 Refresh Token，Refresh Token 的 SHA-256 哈希存储，不存明文。
