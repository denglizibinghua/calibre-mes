## 1. 认证安全

### 1.1 双通道 JWT 隔离

```
┌─────────────────────────────────────────────────┐
│                   JWT 架构                       │
│                                                  │
│  管理端 (Web)          移动端 (小程序)             │
│  ─────────────        ──────────────             │
│  secret-key: admin     secret-key: app            │
│  clientType: admin     clientType: app            │
│  prefix: /admin/**     prefix: /app/**            │
│  login: 用户名+密码     login: wx.login + 账号绑定  │
│                                                  │
│  ⚠️ 两个密钥完全独立，一方泄露不影响另一方         │
└─────────────────────────────────────────────────┘
```

### 1.2 JWT Token 设计

| 属性 | Access Token | Refresh Token | Temp Token |
|------|-------------|---------------|------------|
| 有效期 | 30 分钟 | 7 天 | 5 分钟 |
| 用途 | 业务 API 认证 | 刷新 Access Token | 微信账号绑定 |
| 存储位置 | 前端内存 + localStorage | localStorage + DB(哈希) | 前端内存 |
| 撤销机制 | 短有效期自然过期 | DB 标记 revoked=1 | 短有效期自然过期 |

JWT 声明 (Claims):
```json
{
  "jti": "uuid-string",
  "userId": 123,
  "username": "zhangsan",
  "tokenType": "access|refresh|temp",
  "clientType": "admin|app",
  "iat": 1750000000,
  "exp": 1750001800
}
```

### 1.3 密钥安全验证

```
JwtSecretValidator (启动时执行)
  └─ @Profile("!dev") — 仅非开发环境执行
       ├─ 校验 admin-secret-key 非空 & 长度 ≥ 32
       ├─ 校验 app-secret-key 非空 & 长度 ≥ 32
       ├─ 检查是否包含占位值 ("dev-", "do-not-use", "changeme")
       └─ 不安全 → IllegalStateException → 启动失败
```

### 1.4 Token 刷新与轮换 (Token Rotation)

```
刷新流程：
  1. 前端检测到 401 → 发送 Refresh Token
  2. 后端验证 Refresh Token
     ├─ 签名有效
     ├─ tokenType="refresh"
     ├─ 数据库中存在且未撤销
     └─ 未过期
  3. 生成新的 Access Token + Refresh Token
  4. 旧 Refresh Token → revoked=1, replacedByJti=newJti
  5. 旧 Access Token → 加入短期黑名单(Caffeine缓存, 30min)
  6. 返回新 Token 对
```

## 2. 权限安全 (RBAC)

### 2.1 多层防护

```
第1层: 前端路由守卫
  └─ router.beforeEach → 动态路由加载 (仅加载有权限的页面)
      └─ ⚠️ 纯前端控制，可被绕过

第2层: 前端指令
  └─ v-permission → 控制按钮/元素显隐
      └─ ⚠️ 纯前端控制，可被绕过

第3层: 后端注解 ★ 安全边界
  └─ @RequirePermission("admin:work-order:release")
      └─ PermissionAspect (AOP) → 强制校验
          └─ ✅ 不可绕过

第4层: 数据权限
  └─ dataScope: ALL / DEPT / SELF
      └─ Service 层根据 dataScope 过滤查询结果
```

### 2.2 权限校验流程

```
请求到达 @RequirePermission 方法
  │
  ├─ PermissionAspect (Around Advice)
  │
  ├─ 1. BaseContext.getCurrentId() → userId
  │     └─ null → UnauthorizedException(401)
  │
  ├─ 2. permissionService.hasPermission(userId, requiredPerm)
  │     ├─ Caffeine 缓存命中 → 直接比对
  │     └─ 缓存未命中 → 查询 DB → 缓存
  │           ├─ roleKey="admin" → 通配符 "*:*:*"
  │           └─ 普通角色 → 查 sys_role_menu + sys_menu.perms
  │
  └─ 3. 无权限 → ForbiddenException(403)
```

### 2.3 数据权限过滤

```java
// Service 层根据 dataScope 过滤
switch (dataScope) {
    case "ALL":
        // 无限制，查询全部数据
        break;
    case "DEPT":
        // 只看本部门数据
        queryWrapper.eq("dept_id", userDeptId);
        break;
    case "SELF":
        // 只看自己的数据
        queryWrapper.eq("operator_user_id", userId);
        break;
}
```

## 3. 密码安全

### 3.1 密码策略

| 策略 | 说明 |
|------|------|
| **加密算法** | BCrypt (spring-security-crypto) |
| **复杂度要求** | 8-64位，包含大小写字母+数字+特殊字符 |
| **弱密码黑名单** | "123456", "password", "admin123" 等11个 |
| **用户名检查** | 密码不能包含用户名 |
| **历史密码** | 最近5次密码不能重复使用 |
| **过期时间** | 基于配置 `password.expire_days` |
| **首次登录** | 强制修改密码 (mustChangePassword=1) |
| **管理员重置** | 重置后设置 mustChangePassword=1 |

### 3.2 登录失败锁定

```
登录失败处理 (LoginFailService — Redis):
  │
  ├─ 第1-4次失败: INCR login:fail:{username}
  │     └─ 提示 "用户名或密码错误"
  │
  └─ 第5次失败:
        ├─ 写入 login:lock:{username}（15分钟 TTL）
        └─ 提示 "账户已锁定，请15分钟后再试"

登录成功 / 管理员解锁：删除 login:fail:* 与 login:lock:*。
Redis 不可用时自动降级（不计数不锁定 + 告警日志），不影响登录主流程。
```
登录成功:
  └─ loginFailCount = 0, lockedUntil = NULL
```

### 3.3 密码修改流程

```
PUT /admin/sys-user/change-password
  │
  ├─ ⚠️ 无需 @RequirePermission（安全锁定状态下也可访问）
  │
  └─ SysUserServiceImpl.changePassword(userId, oldPwd, newPwd)
       ├─ 1. 校验旧密码正确
       ├─ 2. PasswordValidator.validate(newPwd) — 复杂度校验
       ├─ 3. 校验不在历史密码中（最近5条）
       ├─ 4. BCrypt 加密存储
       ├─ 5. 记录到 password_history
       ├─ 6. 更新 passwordChangedAt
       ├─ 7. mustChangePassword = 0
       ├─ 8. 撤销该用户所有 Refresh Token
       └─ 9. 清除权限缓存
```

### 4.1 防重复提交机制

```
┌───────────────────────────────────────────────────┐
│              幂等保护全链路                          │
│                                                    │
│  前端                                 后端          │
│  ────                                ────          │
│  idempotencyKey.ts                   ┌──────────┐  │
│  ├─ getOrCreate()                   │Interceptor│  │
│  │   └─ UUID + 10minTTL            │ 提取Header│  │
│  └─ clear() after success           └────┬─────┘  │
│                                          │        │
│  Header: Idempotency-Key: xxx ──────────┘        │
│                                          │        │
│                                   ┌──────▼──────┐ │
│                                   │  Service    │ │
│                                   │ tryAcquire()│ │
│                                   └──────┬──────┘ │
│                                          │        │
│                                   ┌──────▼──────┐ │
│                                   │  DB (MySQL) │ │
│                                   │ 唯一索引     │ │
│                                   │ 实现原子性   │ │
│                                   └─────────────┘ │
└───────────────────────────────────────────────────┘
```

### 4.2 数据库幂等表

## 5. 并发安全

### 5.1 乐观锁 (通用)

```
MyBatis-Plus @Version 注解
  │
  └─ UPDATE table SET ..., version = version + 1
     WHERE id = ? AND version = ?
     │
     └─ affectedRows = 0
          → StateMachineException("数据已被他人修改，请刷新后重试")
```

### 5.2 CAS 原子操作 (关键路径)

```sql
-- 工单完工（防止 TOCTOU）
UPDATE pro_work_order
SET status = '2', actual_end_time = NOW(), version = version + 1
WHERE work_order_id = ? AND status = '1' AND version = ?

-- 工序开始（防止重复开始）
UPDATE pro_work_process
SET status = '1', start_time = NOW(), operator_user_id = ?
WHERE process_record_id = ? AND status = '9' AND version = ?

-- 质检认领（防止多人同时认领）
UPDATE qms_inspection
SET inspector_user_id = ?, inspector = ?, status = '1', version = version + 1
WHERE inspection_id = ? AND inspector_user_id IS NULL AND version = ?
```

## 6. 消息队列安全

### 6.1 安全降级设计

```java
// 配置条件化
@Configuration
@ConditionalOnProperty(name = "app.rabbitmq.enabled", havingValue = "true")
public class RabbitMQConfiguration { ... }

// Service 中安全发送
@Autowired
private ObjectProvider<MessageProducerService> messageProducerProvider;

private void sendWorkOrderMessageSafely(WorkOrderMessageDTO dto) {
    try {
        messageProducerProvider.ifAvailable(producer ->
            producer.sendWorkOrderMessage(dto)

    } catch (Exception e) {
        log.warn("RabbitMQ消息发送失败(不影响业务): {}", e.getMessage());
        // 不抛异常，业务继续
    }
}

## 8. 异常处理安全

### 8.1 异常分类处理

| 异常 | HTTP | 前端提示 | 安全性 |
|------|------|---------|--------|
| BaseException | 200 (code=0) | ex.getMessage() | ✅ 业务可控消息 |
| StateMachineException | 200 (code=0) | "当前状态不允许此操作" | ✅ 固定消息 |
| MethodArgumentNotValidException | 200 (code=0) | 字段级错误详情 | ✅ 参数校验消息 |
| IdempotentKeyMissingException | 400 | "缺少幂等键" | ✅ 固定消息 |
| IdempotentKeyConflictException | 409 | "幂等键冲突" | ✅ 固定消息 |
| UnauthorizedException | 401 | "未登录或登录已过期" | ✅ 固定消息 |
| ForbiddenException | 403 | "无权限" | ✅ 固定消息 |
| DuplicateKeyException | 200 (code=0) | "数据已存在" | ✅ 解析唯一键名 |
| DataIntegrityViolationException | 200 (code=0) | FK/NOT NULL友好提示 | ✅ 解析约束名 |
| Exception (兜底) | 500 | "系统繁忙" + requestId | ✅ 堆栈不暴露 |

### 8.2 兜底异常响应

```json
{
  "code": 500,
  "msg": "系统繁忙，请稍后重试",
  "timestamp": "2026-07-25T10:30:00",
  "path": "/admin/pro-work-order/123/release",
  "requestId": "a1b2c3d4"
}
```

- `requestId` 为 UUID 前8位，用于日志关联排查
- 完整堆栈仅输出到 `log.error()`，不返回到前端
- 不暴露 SQL 语句、服务器路径、数据库信息

## 9. CORS 配置

```java
// WebMvcConfiguration
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/**")
        .allowedOriginPatterns("*")        // 所有来源
        .allowedMethods("*")               // 所有HTTP方法
        .allowedHeaders("*")               // 所有请求头

## 10. Redis 缓存与 WebSocket 实时推送

### 10.1 Redis

- 登录失败锁定：`INCR login:fail:{username}` + `login:lock:{username}`（15 分钟 TTL），登录成功/管理员解锁删除
- 权限与数据范围缓存：Caffeine 本地一级 + Redis 二级（`perm:{userId}` / `datascope:{userId}`，30 分钟 TTL），角色变更事件双清
- 系统配置缓存：`config:byId:{id}` / `config:key:{key}`（24 小时 TTL），增删改自动失效
- 所有 Redis 操作异常自动降级（回源 DB / 告警日志），不影响主业务

### 10.2 WebSocket 实时推送

- 端点 `/ws`，握手携带 `?token=`（JWT，校验 access 类型 + clientType 合法性）
- `WsSessionManager` 按 clientType + userId 管理连接；`WebSocketNotifier` 推送给管理端全量或指定用户
- 推送事件：安灯（创建/受理/关闭/升级）、工单（下达/开工/完工）、质检（确认）、维修（受理/完工）
- Web 与小程序均 30s ping / 10s pong 超时，断线按 1/2/4/8/16/30s 退避重连；退出、认证最终失效时停止连接，正常 token 刷新保留订阅
- 五类业务通知在事务提交后发送，回滚不发送；timestamp 固定 ISO 本地日期时间字符串
- Web 六列表、小程序安灯/维修页恢复连接后通过原 API 补查，迟到旧响应不能覆盖新数据
- 开发 Vite 配置 `/ws` upgrade 代理，生产空基地址走同源代理并在 HTTPS 下采用 WSS
- 2026-10-31 实现与验证清单见 [WebSocket 交付说明](websocket-delivery.md)，含单实例、生产和真机验证边界

## 10. 数据安全

### 10.1 敏感数据保护

| 数据 | 保护措施 |
|------|---------|
| 密码 | BCrypt 加密存储，永不明文 |
| Refresh Token | 数据库仅存 SHA-256 哈希，不存明文 |
| JWT 密钥 | 环境变量注入，不硬编码 |
| 微信 AppSecret | 环境变量注入，不硬编码 |
| 操作日志中的密码 | `@ToString.Exclude` 排除 |
| SQL 查询 | MyBatis-Plus 参数化查询，防注入 |

### 10.2 日志安全

```
禁止:
  ✗ log.info("password: {}", password)
  ✗ log.info("token: {}", jwtToken)
  ✗ log.info("secret: {}", appSecret)

允许:
  ✓ log.info("用户 {} 登录成功", username)
  ✓ log.info("工单 {} 已下达", workOrderNo)
  ✓ log.error("RabbitMQ发送失败: {}", e.getMessage())  // 不含堆栈
```
