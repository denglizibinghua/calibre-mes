## 1. 认证与授权调用链

### 1.1 管理端登录流程

```
用户 → 浏览器 → POST /admin/user/login → UserController.login()
  │
  └─ SysUserServiceImpl.login(UserLoginDTO)
       ├─ 1. findByUsername(username) → sys_user
       ├─ 2. 检查 lockedUntil > now → "账户已锁定"
       ├─ 3. BCryptPasswordEncoder.matches(password, hash)
       │     └─ 失败 → LoginFailService.incrementFailCount() [REQUIRES_NEW]
       │           └─ 失败 ≥ 5次 → 锁定15分钟
       ├─ 4. 检查 status="1" → "账户已禁用"
       ├─ 5. 成功 → 重置 loginFailCount=0, lockedUntil=null
       ├─ 6. 检查密码过期 → passwordExpired 标记
       ├─ 7. JwtUtil.createAccessToken(userId, "admin")
       │     └─ 声明: jti(UUID), userId, tokenType="access", clientType="admin"
       │     └─ 签名: admin-secret-key (HS256), 30分钟过期
       ├─ 8. JwtUtil.createRefreshToken(userId, "admin")
       │     └─ 声明: tokenType="refresh", 7天过期
       ├─ 9. SHA-256(refreshToken) → user_refresh_token 表
       ├─ 10. PermissionService.getUserPermissions(userId)
       │      └─ sys_role_menu JOIN sys_menu → Caffeine缓存(30min)
       └─ 11. 返回 UserLoginVO { accessToken, refreshToken, permissions, dataScope, ... }
```

### 1.2 JWT 拦截器校验链路（每个请求）

```
HTTP Request → JwtTokenAdminInterceptor.preHandle()
  │
  ├─ 1. 跳过 OPTIONS（CORS 预检）
  ├─ 2. 提取 token 请求头
  ├─ 3. JwtUtil.parseToken(token, adminSecretKey)
  │     ├─ 校验签名
  │     ├─ 校验过期时间
  │     ├─ 校验 tokenType="access"（非 refresh）
  │     └─ 校验 clientType="admin"（非 app）
  ├─ 4. 查询 sys_user → 校验用户存在 & status≠"1"
  ├─ 5. 密码安全检查
  │     ├─ mustChangePassword=1 或 passwordExpired=true
  │     └─ → 仅放行安全接口(/change-password, /logout, /menus, /refresh-token)
  │         └─ 否则 → 403 + errorCode="SECURITY_PASSWORD_CHANGE_REQUIRED"
  ├─ 6. PermissionService.getUserPermissions(userId) → Caffeine
  │     ├─ role_key="admin" → 返回通配符 "*:*:*"
  │     └─ 否则 → 查询 sys_role_menu + sys_menu.perms
  ├─ 7. PermissionService.getUserDataScope(userId)
  │     └─ ALL / DEPT / SELF
  ├─ 8. 写入 BaseContext (ThreadLocal)
  │     ├─ currentId = userId
  │     ├─ currentPermissions = [权限码列表]
  │     ├─ currentDataScope = "ALL"|"DEPT"|"SELF"
  │     ├─ currentClientType = "admin"
  │     └─ currentTokenJti = jti
  └─ 9. 放行 → Controller
       └─ afterCompletion → BaseContext.removeAll()
```

### 1.3 Token 刷新流程

```
前端 401 → POST /admin/user/refresh-token → UserController.refreshToken()
  │
  └─ RefreshTokenServiceImpl.refreshAccessToken(refreshToken)
       ├─ 1. JwtUtil.parseToken(refreshToken, adminSecretKey)
       │     └─ 校验: tokenType="refresh", clientType="admin"
       ├─ 2. SHA-256(refreshToken) → 查询 user_refresh_token
       │     └─ 校验: 未撤销(revoked=0), 未过期
       ├─ 3. 生成新 accessToken (30min)
       ├─ 4. Token Rotation:
       │     ├─ 旧 refreshToken → revoked=1, replacedByJti=newJti
       │     └─ 新 refreshToken → INSERT, hash=新hash
       ├─ 5. 立即撤销旧 accessToken（加入黑名单缓存）
       └─ 6. 返回 newAccessToken + newRefreshToken
```

### 1.4 微信小程序登录流程

```
用户打开小程序 → wx.login() → 获取 code
  │
  └─ POST /app/user/wx-login → UserController.wxLogin(WxLoginDTO)
       │
       └─ WechatServiceImpl.wxLogin(code)
            ├─ 1. 调用微信 API: code2Session(code) → openid
            ├─ 2. 查询 sys_user WHERE openid=?
            │     ├─ 已绑定(status=1):
            │     │     ├─ 生成 accessToken + refreshToken
            │     │     ├─ 加载权限
            │     │     └─ 返回 WxLoginVO { accessToken, refreshToken, userInfo }
            │     └─ 未绑定(status=2):
            │           ├─ 生成 tempToken (5分钟有效, tokenType="temp")
            │           └─ 返回 WxLoginVO { tempToken, status=2 }
            │
            └─ 绑定流程:
                 POST /app/user/wx-bind → UserController.wxBind(WxBindDTO)
                   │
                   └─ WechatServiceImpl.bindAccount(tempToken, username, password)
                        ├─ 校验 tempToken 有效性
                        ├─ 校验用户名密码
                        ├─ 更新 sys_user.openid = openid
                        └─ 生成正式 token
```

## 2. 工单状态机调用链

### 2.1 工单下达

```
PUT /admin/pro-work-order/{id}/release
  │
  ├─ @RequirePermission("admin:work-order:release")
  ├─ @IdempotencyRequired
  │
  └─ ProWorkOrderServiceImpl.releaseWorkOrder(id, dto)
       ├─ 1. getById(id) → ProWorkOrder entity
       ├─ 2. StatusTransitionValidator.canTransition(CREATED, RELEASED)
       │     └─ 非法 → StateMachineException("当前状态不允许此操作")
       ├─ 3. IdempotencyService.tryAcquire(key, "WORK_ORDER", "RELEASE", hash, userId)
       │     ├─ INSERT IGNORE pro_idempotency_record (唯一索引)
       │     ├─ SUCCESS同参数 → 返回缓存结果 (DUPLICATE)
       │     ├─ PROCESSING超时 → 接管重试 (ACQUIRED)
       │     └─ 不同参数同key → IdempotentKeyConflictException (409)
       ├─ 4. BeanUtils.copyProperties(dto, entity)
       ├─ 5. entity.setStatus(RELEASED)
       ├─ 6. updateById(entity) [@Version 乐观锁]
       ├─ 7. ProWorkProcessMapper 批量插入工序记录 (根据 route.stepsJson)
       │     └─ 首道工序状态 = READY("9"), 其余 = PENDING("0")
       ├─ 8. StatusTransitionLogService.log(entityType, id, CREATED, RELEASED, "RELEASE")
       ├─ 9. MQ发送: sendWorkOrderMessageSafely(WorkOrderMessageDTO)
       │     └─ try-catch: MQ失败只记录日志, 不影响业务
       └─ 10. IdempotencyService.markSuccess(key)
```

### 2.2 工单完整状态流转

```
CREATED("0")  ──release──▶  RELEASED("4")
                                │
                    ┌───────────┼───────────┐
                    ▼           ▼           ▼
              cancel    auto-start    manual-start
                    │           │           │
                    ▼           ▼           ▼
              CANCELLED("6") IN_PROGRESS("1")
                                 │
                    ┌────────────┼────────────┐
                    ▼            ▼            ▼
               PAUSED("5")  COMPLETED("2")  (所有工序完成)
                    │            │
                    ▼            ▼
               resume      CLOSED("3")
                    │
                    ▼
              IN_PROGRESS("1")
```

**终态**：CLOSED("3")、CANCELLED("6")

## 3. 工序状态机调用链（最复杂的流转）

### 3.1 工序开始

```
PUT /app/pro-work-process/{id}/start
  │
  ├─ @RequirePermission("app:work-process:start")
  ├─ @IdempotencyRequired
  │
  └─ ProWorkProcessServiceImpl.startProWorkProcess(id)
       ├─ 1. getById(id) → 校验 status=READY("9")
       ├─ 2. 校验工单状态：workOrder.status ∈ {RELEASED, IN_PROGRESS}
       ├─ 3. 校验前序工序已完工（stepSeq检查）
       ├─ 4. CAS 更新:
       │     UPDATE pro_work_process
       │     SET status='1', start_time=NOW(), operator_user_id=?
       │     WHERE process_record_id=? AND status='9' AND version=?
       ├─ 5. 如果工单状态=RELEASED → CAS 更新工单为 IN_PROGRESS
       ├─ 6. 更新 equipment.running_status = "USED"（如果绑定设备）
       └─ 7. StatusTransitionLogService.log(...)
```

### 3.2 统一报工（含质检判定）

```
PUT /app/pro-work-process/{id}/report
  │
  ├─ @RequirePermission("app:work-process:report")
  ├─ @IdempotencyRequired
  │
  └─ ProWorkProcessServiceImpl.unifiedReport(id, dto)
       ├─ 1. getById(id) → 校验 status=IN_PROGRESS("1")
       ├─ 2. 判断是否需要质检:
       │     ├─ process.needInspection=true → goto 3a（需要质检）
       │     └─ process.needInspection=false → goto 3b（无需质检）
       │
       ├─ 3a. 【需要质检】reportWithInspection()
       │     ├─ CAS 更新: status='3' (WAIT_INSPECTION)
       │     ├─ 插入 qms_inspection（状态=PENDING）
       │     ├─ 更新 equipment.running_status = "NORMAL"
       │     └─ 返回 质检单信息
       │
       ├─ 3b. 【无需质检】直接完工
       │     ├─ CAS 更新: status='2' (COMPLETED)
       │     ├─ 更新 equipment.running_status = "NORMAL"
       │     ├─ 触发下一道工序: markNextProcessAsReady()
       │     │     └─ UPDATE status='9' WHERE status='0' AND stepSeq=next
       │     ├─ 检查工单所有工序是否都已完工
       │     │     └─ 是 → CAS 更新工单: status='2' (COMPLETED)
       │     └─ MQ发送: sendWorkOrderMessageSafely(...)
       │
       └─ 4. StatusTransitionLogService.log(...)
```

### 3.3 质检确认 → 自动联动工序状态

```
PUT /admin/qms-inspection/{id}/confirm
  │
  ├─ @RequirePermission("admin:inspection:confirm")
  ├─ @IdempotencyRequired
  │
  └─ QmsInspectionServiceImpl.confirmInspection(id, dto)
       ├─ 1. getById(id) → 校验 status=ENTERED("1")
       ├─ 2. 根据检验项目结果计算总体结论
       │     ├─ 全部通过 → qcResult = PASS
       │     └─ 任一不通过 → qcResult = FAIL
       ├─ 3. 更新检验单: status='2' (CONFIRMED), confirmedBy, confirmTime
       │
       └─ 4. 【事务内联动】syncProcessStatusAfterConfirm()
            ├─ 如果是通过(PASS):
            │     ├─ CAS 更新工序: status='4' (QUALIFIED)
            │     └─ CAS 更新工序: status='2' (COMPLETED)
            │           └─ 触发下一道工序 ready
            │
            ├─ 如果是不通过(FAIL):
            │     ├─ CAS 更新工序: status='5' (REJECTED)
            │     └─ 创建返工检验单(parentInspectionId指向当前)
            │
            └─ MQ发送: QualityMessageDTO
```

### 3.4 返工闭环

```
REJECTED("5") ──rework-start──▶  REWORK("6") ──rework-complete──▶  WAIT_INSPECTION("3")
                                                                        │
                                                              ┌─────────┘
                                                              ▼
                                                       质检确认 (循环)
```

```
PUT /app/pro-work-process/{id}/rework-start
  │
  └─ ProWorkProcessServiceImpl.operatorReworkStart(id)
       ├─ 1. 校验 status=REJECTED("5")
       ├─ 2. CAS 更新: status='6' (REWORK)
       ├─ 3. 更新 equipment.running_status = "USED"
       └─ 4. reworkCount++

PUT /app/pro-work-process/{id}/rework-complete
  │
  └─ ProWorkProcessServiceImpl.operatorReworkComplete(id)
       ├─ 1. 校验 status=REWORK("6")
       ├─ 2. CAS 更新: status='3' (WAIT_INSPECTION) — 强制重新质检
       ├─ 3. 更新 equipment.running_status = "NORMAL"
       └─ 4. StatusTransitionLogService.log(...)
```

### 3.5 完整工序状态流转图

```
                         ┌──────────────┐
                         │  PENDING("0") │ 待开始
```

## 4. 质检管理调用链

### 4.1 检验单创建（自动触发）

```
报工送检 → ProWorkProcessServiceImpl.reportWithInspection()
  │
  └─ 自动创建检验单:
       ├─ INSERT qms_inspection:
       │     inspectionNo = 自动生成
       │     workOrderId = 当前工单
       │     processId = 当前工序
       │     processRecordId = 当前工序记录ID（精确关联）
       │     status = PENDING("0")
       │     inspectionRound = 1
       ├─ 根据工序的检验项目模板 → INSERT qms_inspection_item × N
       └─ 返回 inspectionId 供后续操作
```

### 4.2 检验结果录入（原子认领）

```
PUT /admin/qms-inspection/{id}/result
  │
  └─ QmsInspectionServiceImpl.enterInspectionResult(id, dto)
       ├─ 1. getById(id) → 校验 status=PENDING("0")
       ├─ 2. 【原子认领】CAS 更新:
       │     UPDATE qms_inspection
       │     SET inspector_user_id=?, inspector=?, status='1', version=version+1
       │     WHERE inspection_id=? AND inspector_user_id IS NULL AND version=?
       │     └─ 防止两个质检员同时认领
       ├─ 3. 批量保存检验项目结果:
       │     For each item in dto.items:
       │       UPDATE qms_inspection_item
       │       SET actual_value=?, check_result=PASS/FAIL
       │       WHERE item_id=?
       ├─ 4. 计算整体结果: result = (全部PASS ? PASS : FAIL)
       ├─ 5. 更新检验单: result=computed, detailsJson=序列化
       └─ 6. StatusTransitionLogService.log(...)
```

### 4.3 检验确认 → 联动工序（核心业务闭环）

见 3.3 节。

## 8. 幂等性调用链

### 8.1 完整幂等流程

```
前端: idempotencyKey = getOrCreate("report:123")
  │
  ▼
HTTP Header: Idempotency-Key: a1b2c3d4-...
  │
  ▼
IdempotencyInterceptor.preHandle()
  ├─ @IdempotencyRequired 注解检查
  └─ BaseContext.setIdempotencyKey(key)
  │
  ▼
Service 层:
  ├─ 1. tryAcquire(key, bizType, action, paramsHash, userId)
  │     ├─ INSERT IGNORE pro_idempotency_record
  │     │     (idempotency_key, business_type, action, operator_id)
  │     │     └─ 唯一索引保证原子性
  │     │
  │     ├─ 插入成功 → ACQUIRED → 执行业务逻辑
  │     │
  │     ├─ 已存在 & 状态=SUCCESS & hash相同
  │     │     └─ → DUPLICATE → 返回缓存结果（不重复执行）
  │     │
  │     ├─ 已存在 & 状态=SUCCESS & hash不同
  │     │     └─ → IdempotentKeyConflictException (409)
  │     │
  │     ├─ 已存在 & 状态=PROCESSING & 未超时(5min)
  │     │     └─ → 返回 "请求处理中, 请稍候"
  │     │
  │     └─ 已存在 & 状态=PROCESSING & 已超时
  │           └─ → ACQUIRED → 接管重试
  │
  ├─ 2. 执行业务逻辑
  │
  ├─ 3. 成功 → markSuccess(key, responseData)
  │     └─ UPDATE pro_idempotency_record SET process_status=1, response_data=?
  │
  └─ 4. 失败 → markFailure(key)
        └─ UPDATE pro_idempotency_record SET process_status=2
```


## 10. 并发控制调用链

### 10.1 通用乐观锁（MyBatis-Plus @Version）

```
updateById(entity)
  │
  └─ MyBatis-Plus OptimisticLockerInnerInterceptor
       └─ SQL自动添加:
            UPDATE xxx SET ..., version = version + 1
            WHERE id = ? AND version = ?
            └─ affected rows = 0 → StateMachineException("数据已被他人修改")
```

### 10.2 关键路径CAS（防TOCTOU）

```sql
-- 工单完工（原子性检查）
UPDATE pro_work_order

WHERE work_order_id = ? AND status = '1' AND version = ?

-- 工序状态转换
```

## 11. 异常处理调用链

```
Controller / Service 抛出异常
  │
  ▼
GlobalExceptionHandler (@RestControllerAdvice)
  │
  ├─ BaseException / StateMachineException
  │     └─ Result.error(msg) + HTTP 200 + code=0
  │
  ├─ MethodArgumentNotValidException
  │     └─ Result.error(字段名+错误信息) + HTTP 200
  │
  ├─ IdempotentKeyMissingException → HTTP 400 + code=400
  ├─ IdempotentKeyConflictException → HTTP 409 + code=409
  │
  ├─ UnauthorizedException → HTTP 401 + code=401
  ├─ ForbiddenException → HTTP 403 + code=403
  │
  ├─ DuplicateKeyException
  │     └─ Result.error("数据已存在，请勿重复操作")
  │
  ├─ DataIntegrityViolationException
  │     └─ 解析 cause: FK约束/NOT NULL/Data too long
  │
  └─ Exception (兜底)
        └─ Result.error("系统繁忙")
             + requestId(UUID前8位)
             + path
             + timestamp
             └─ 堆栈仅打日志，不暴露给前端
```

## 12. 缓存调用链

### 12.1 权限缓存

```
PermissionService.getUserPermissions(userId)
  │
  ├─ cache.get(userId) → 命中就返回
  │
  └─ 未命中:
       ├─ 查询 sys_role WHERE user.roleId
       │     └─ roleKey="admin" → 通配符 ["*:*:*"]
       ├─ 查询 sys_role_menu JOIN sys_menu
       │     └─ 收集 menu.perms 字段
       ├─ cache.put(userId, permissions) [30min TTL]
       └─ 返回 permissions
```
