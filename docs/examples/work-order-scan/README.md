## 操作步骤

1. 启动更新后的后端，在管理端使用有 `admin:work-order:view` 权限的账号进入工单管理。
2. 搜索 `MO-20261024-0040`，点击该行“工单二维码”，可查看并下载 PNG。也可以直接展示本目录图片供小程序扫描。
3. 微信开发者工具导入 `D:\code\Java\bike-assembly-mes\bike-assembly-mes-miniapp\dist\dev\mp-weixin`，或者导入已同步构建的 `dist\build\mp-weixin`。不要将源码目录直接作为微信原生项目导入。
4. 操作员使用已分配系统账号登录，点击底部扫码。当前真实工单指派给 `operator01`，可选择查看工单或进入该工单的工序报工。
5. 质检员使用 `inspector01` 登录，扫描相同码，进入该工单待质检任务。该账号访问此工单详情会返回 403，但质检路径可以独立工作。
6. 进入页面后仍需人工选择工序并执行开工/报工，或人工录入/确认质检。扫码和页面加载不会自动执行业务写操作。

扫码定位可使用页面上的“清除扫码定位”解除；质检页保留工单搜索、待检/已检、确认状态和检验结果筛选。

## 失败验证

- `https://example.test/evil`：无效码，不跳转外部地址。
- `BIKE-MES:2:WORK_ORDER:40`：版本不支持。
- `BIKE-MES:1:ITEM:40`：业务类型不支持，本期不支持物料或设备扫码。
- `BIKE-MES:1:WORK_ORDER:9007199254740991`：当前库不存在此工单，返回明确不存在提示。
- `viewer01` 扫描本例：不是工单执行人且无对应全部数据权限，拒绝访问。
- `maintainer01` 扫描本例：没有工单、工序、质检查看入口，拒绝访问。
- 无待检工单：质检员收到“当前工单暂无可访问的待质检任务”，不转而显示其他工单。
- 取消扫码：静默返回，允许再次扫码。
- 拒绝摄像头授权：提示在微信设置中开启摄像头权限，提供设置入口。

后续生产操作可能改变这张工单的状态或消耗待检任务；示例码仍指向工单 40，预期入口以当时后端权限与数据为准。生产环境应从自己的真实工单列表下载二维码。
