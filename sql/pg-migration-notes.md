# MySQL 8 → PostgreSQL 16 迁移说明（sql/ 手写 SQL 层）

目标库：PostgreSQL 16.16，容器 `xiaoxueqi-pgvector-1`，数据库 `bike_assembly_mes`，
用户 `mes`，编码 UTF8，`LC_COLLATE=C`。所有脚本均以 psql + `ON_ERROR_STOP=1` 执行。

## 1. 类型映射

| MySQL 8 | PostgreSQL 16 | 说明 |
| --- | --- | --- |
| `BIGINT AUTO_INCREMENT` | `bigint GENERATED BY DEFAULT AS IDENTITY` | `BY DEFAULT` 允许种子数据显式插入 id；`ALWAYS` 会失败 |
| `INT AUTO_INCREMENT` | `integer GENERATED BY DEFAULT AS IDENTITY` | 现有表主键均为 BIGINT |
| `INT` / `INTEGER` | `integer` | 保留原列宽 |
| `BIGINT` | `bigint` | 保留原列宽 |
| `VARCHAR(n)` | `varchar(n)` | 不变 |
| `CHAR(1)` | `char(1)` | 状态位 / 类型位，Java 侧按 String 绑定 |
| `DECIMAL(18,4)` | `numeric(18,4)` | 数量、金额 |
| `DATETIME` | `timestamp(0) without time zone` | 与 MySQL 默认秒精度对齐；Java `LocalDateTime` 直接映射 |
| `TIMESTAMP` + `DEFAULT CURRENT_TIMESTAMP` | `timestamp(0) NOT NULL DEFAULT CURRENT_TIMESTAMP` | 同上 |
| `... ON UPDATE CURRENT_TIMESTAMP` | `BEFORE UPDATE` 触发器 `set_updated_at()` | PostgreSQL 没有列级 ON UPDATE |
| `JSON`（Java 绑定 `String`） | `text` | **不是 jsonb**：`WmsStockDocMapper` 使用 `details_json LIKE`，json/jsonb 不支持 LIKE，且 Java 层绑定纯字符串，无需任何 cast |
| `TINYINT` 且 Java 字段为 `Boolean` | `boolean` | 仅 `ai_request_audit.fallback`（`AiRequestAudit.fallback` 是 `Boolean`） |
| 其余 `TINYINT` | `smallint` | `sys_user.must_change_password`、`user_refresh_token.revoked` 的 Java 字段是 `Integer`，用 `smallint` 避免 JDBC 类型不匹配 |
| `MEDIUMBLOB` | `bytea` | `user_face_template.embedding_ciphertext` |
| `TEXT` | `text` | 不变 |
| `UNSIGNED` | 去掉 | 现有 DDL 未使用无符号 |
| `ENGINE=InnoDB / DEFAULT CHARSET / COLLATE` | 删除 | PostgreSQL 库级编码为 UTF8 |
| 反引号 | 删除 | PostgreSQL 使用双引号（本层全部标识符均为小写，无需引用） |
| 表级 `COMMENT '...'` | `COMMENT ON TABLE`（init_database.sql 末尾） | 列注释未迁移，属于可选低优先级项 |
| MySQL STORED 生成列 | `GENERATED ALWAYS AS (expr) STORED` | `qms_inspection.active_task_key` 原生支持 |
| `SET FOREIGN_KEY_CHECKS=0/1` | 删除 | 建表后统一加 FK；重建用 `DROP TABLE ... CASCADE` |
| `INSERT ... ON DUPLICATE KEY UPDATE x=VALUES(x)` | `ON CONFLICT (<唯一键>) DO UPDATE SET x=EXCLUDED.x` | 冲突目标：`role_id`、`menu_id`、`user_id`、`config_key` 等 |
| `INSERT IGNORE` | `ON CONFLICT (<主键>) DO NOTHING` | 测试种子脚本 |
| `DATE_ADD/DATE_SUB/DATE_FORMAT/TIMESTAMP()/INTERVAL` | 生成阶段在 Node.js 中计算，输出 `'YYYY-MM-DD HH:MM:SS'` 字面量 | 生成文件不含任何 SQL 日期函数 |
| `@seed_*` 会话变量 | 删除 | 角色 id / 姓名改为内联标量子查询；生成文件不含会话变量 |
| `CREATE/DROP TEMPORARY TABLE demo_seed_guard` | `DO $$ ... RAISE EXCEPTION ... $$` | 种子前置校验 |
| `ALTER TABLE qms_inspection MODIFY inspection_time ...` | 删除 | DDL 中该列已是 nullable，无需运行期修改表结构 |

## 2. 语义差异与处理

- **序列**：显式 id 插入后，所有 identity 表执行
  `setval(pg_get_serial_sequence('t','id'), COALESCE(MAX(id),0)+1, false)`，
  保证后续应用插入不撞主键。`init_database.sql` 覆盖 5 张系统表；
  `dev_seed_full.sql` 覆盖 21 张业务表；`seed_production_flow.sql` 覆盖 7 张。
- **唯一键名**：`uk_*` 保留为 `CONSTRAINT uk_* UNIQUE (...)`；普通索引名保留。
  PostgreSQL 索引名 schema 级唯一，现有命名本身不冲突。
- **NULL 唯一性**：PostgreSQL 与 MySQL 一致，多行 NULL 不冲突
  （`uk_sys_user_openid`、`uk_qms_active_by_record`）。
- **字符串转义**：`standard_conforming_strings=on`，生成器只把 `'` 翻倍，不再转义反斜杠，
  否则 JSON 文本里的 `\"` 会被破坏。
- **事务**：`dev_seed_full.sql` 先 `BEGIN` 再 `DELETE`/`INSERT`/校验，失败整体回滚。
- **校验脚本**：`CREATE TEMPORARY TABLE demo_validation_result (violations bigint CHECK (violations=0))`，
  任一检查非零即抛 `23514`，psql `ON_ERROR_STOP` 返回非零。
- **校验用 JSON 解析**：`details_json` 等列是 `text`，校验脚本为读取结构使用
  `details_json::jsonb` / `jsonb_array_elements`。这类 cast 只存在于 `verify_database.sql`
  的校验 SQL 中；应用侧 DDL 与业务查询保持零 cast。
- **校验时间基准**：校验脚本把 `NOW()` 替换为生成时刻字面量（例如 `'2026-11-15 12:22:33'`），
  因此生成文件同样不含 SQL 日期函数，且校验比"运行到此刻"更严格。
- **时区**：所有时间均为不带时区的本地时间，与 MySQL `DATETIME` 行为一致。

## 3. 补丁幂等策略

- 建表：`CREATE TABLE IF NOT EXISTS`。
- 加列：`DO $$ BEGIN IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_schema=current_schema() AND table_name=... AND column_name=...) THEN ALTER TABLE ... ADD COLUMN ...; END IF; END $$;`
- 加索引：`IF to_regclass('idx_...') IS NULL THEN CREATE INDEX ...;`
- `user_face_template` 的 FK 与触发器：`init_database.sql` 重建时 `DROP TABLE sys_user CASCADE`
  会移除该 FK，补丁用 `pg_constraint` / `pg_trigger` 守卫重新补上。
- 菜单：`ON CONFLICT (menu_id) DO UPDATE`；角色菜单用 `NOT EXISTS` 防重。

## 4. 已知差异（不影响执行）

- MySQL 会为外键自动创建同名索引（如 `fk_aa_work_order_id`），PostgreSQL 不会；
  `init_database.sql` 只保留原脚本显式声明的索引。外键校验不受影响。
- 列注释未迁移（架构决策中的可选项）。
- `dev_seed_full.sql` 数据量沿用生成器完整数据集（48 工单 / 368 工序 / 1828 流水），
  高于 `D:\temp\mes_backup_pre_pg_20261115.sql` 中旧演示数据（5 工单）——未缩减任何数据。
